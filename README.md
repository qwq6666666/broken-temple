# 破廟宗主

純 HTML + CSS + ES Modules 的放置遊戲，不需打包。

## 執行
ES Modules 在 `file://` 會被瀏覽器擋，請用本機伺服器：

```bash
npx serve .
```

測試／調數值：網址加 `?speed=10`（遊戲時間 10 倍速）。加 `?perf` 會每 5 秒在 console 印出 render／tick 的平均與最大耗時（25 位弟子、15 位仇人時每幀約 0.4～0.8ms，不需優化）。Console 可用 `__game.state` 直接改資源。

```bash
node tests/run.mjs           # 核心邏輯測試（保底、成本、連鎖、tick 線性…）；或 npm test
node tests/invariants.mjs 1 12   # 核心壓力：機器人連續多輪轉生，檢查不變量與存檔往返（有問題時結束碼非 0）；npm run test:invariants
node tests/e2e/run.mjs       # 瀏覽器端到端（桌面＋手機）：版面溢出掃描與全操作覆蓋（含建築 ×10／最大批量升級）；需 npm i -D playwright，未安裝會略過；E2E_VERBOSE=1 列出每一項；npm run test:e2e
node tests/sim.mjs 40       # 平衡模擬器：貪婪機器人跑 40 小時，印出各里程碑時間
node tests/sim.mjs 40 passive   # 同上但完全不打坐（純掛機）
node tests/sim.mjs 40 active rebirth   # 化神後自動轉生並購買道心，印出每一輪耗時
node tests/sim.mjs 12 equip branch commission insight smart   # 開啟新功能的最佳化機器人（裝備法寶、弟子進階、領委託、領悟專長心得、用「補滿空位」派駐）
node tests/sim.mjs 40 equip branch commission insight smart rebirth ascend   # 再加 ascend：機器人順勢渡劫並買道果，印出各天劫在第幾世達成；RUNSTATS=1 會印出每輪的連鎖／事件／忍／秘境（調天劫門檻用）
ELEMENT=0 node tests/sim.mjs 12   # 關閉五行相生相剋／克制當比較基準；SHENG/KE/ENEMY_BEAT 可覆寫數值；SEED 指定亂數種子
```

調數值時先跑 sim。單一亂數種子結果雜訊很大（同設定化神耗時可差 ±20%），比較設定請多種子取平均。
目前節奏（16 種子平均，機器人偏樂觀）：首次引爆約 15 分；首輪到化神約 **3.7 小時**（含打坐、機器人隨手把弟子塞進第一個空位）；**會依專長／五行派駐的玩家（`smart`，用「補滿空位」）約 2.2～2.5 小時**——專長相符 ×2 原本就是最大的玩家技巧差距。之後每輪轉生約 2 小時、道心約 50。
新功能各自對首輪到化神的影響（最佳化機器人上限）：法寶裝備 −2%、弟子進階 −3%、宗門委託 −7%、五行相生相剋 −5%、專長心得 −2%，仇人五行克制幾乎無影響；全開約 −20%（smart 派駐基準 2.49 → 1.90）。
注意：16 種子平均本身有約 ±6% 的雜訊（關閉效果但保持啟用，與完全停用就差 5%；曾有一次 16 種子量到 −11% 但 48 種子下為 0），要下結論請用 48 種子（約 1 分鐘）。補滿空位的建築價值加權（`config.assignValue`）與等權在 48 種子下無顯著差異。
宗門委託對平衡很敏感：早期靈石獎勵下限（`stoneMin`）若設 20（早期突破只要 4 靈石），化神會快 13～19%，現為 4。
## 建築等級刻度（0～100 級）
- 建築等級上限 100（`CONFIG.building.maxLevel`），由境界決定：`10 + floor(境界序號 × 6.93)`，凡人 10 級、化神 100 級（`capAtRealm`）。破廟開局 10 級。
- **資料仍用舊刻度書寫**（`data/buildings.js` 的 `baseCost`、`produce`，各建築的每級效果），程式再除以 `CONFIG.building.levelScale`（10）：成本 = 基礎 ÷ 10 × 1.0141^等級 × 境界倍率；功能型建築 10 級 ≈ 舊版 1 級（`core/buildingMath.js` 的 `lvEff`）。升滿 100 級的累計成本與舊制相近。
- 破廟／靈田／煉丹房的每級產出 = 舊值 ÷ 10 ÷ 1.4，再乘**里程碑倍率**（Lv10 ×1.1、25 ×1.25、50 ×1.5、75 ×1.75、100 ×2，累計，`CONFIG.building.milestones`）。這個設計讓一輪的節奏與舊制中性（24 小時 8 種子：首輪化神 3.02 vs 3.03 小時、道心/小時 −0.8%，在雜訊內）；前期稍弱、化神滿級約強 43%。
- 駐守位每 30 級 +1（第 1／31／61／91 級）；專精要 Lv50（`SPEC_LEVEL`）；外觀階段門檻、「全建築」大事門檻（30／50／100）都已 ×10。
- 介面：每棟有「升級」「×10」「最大」，「⚡ 全部升級」一次升到買不起（含批量，只播一次提示）。舊存檔（v2 以前）載入時等級 ×10（`SAVE_VERSION` 3）。
- **擴建（第二層）**：道心商店「🏗️ 擴建」每級 +10 建築等級上限，最多 90 級（+900，絕對上限 1000），成本 15 道心 × 1.05^級（買滿約 2.4 萬道心）。加成**隨境界逐步生效**（凡人 0、化神全額，`capAtRealm(i, extra)`），所以每一輪都感覺得到，又不會繞過境界；轉生保留。
- 100 級以上：產出里程碑每 100 級再 ×1.25（1000 級累計 ×14.9）；功能型建築效果遞減（`lvEff` 每翻倍只 +3，1000 級約為 100 級的 2 倍），折扣、戰力、機率不會失控。
- 平衡（24 小時、8 種子，`EXTRA=N` 直接給擴建 +N 級）：+100／300／600／900 級，首輪化神約快 6～9%、道心/小時 +2～5%，已趨飽和（成本成長遠快於產出成長），不會失控。`affordableLevels(s, id, 2)` 供介面每幀判斷「×10／最大」可按與否（0.08 ms／幀）。

## 弟子頁：方塊角色牌 + 彈出面板
- 弟子以**正方形角色牌**排列（手機一排 3 張、桌面約 6 張）：大頭像、名字、等級星級、派駐狀態；稀有度用邊框色（SSR／UR 有光暈）。左上圖示表示有事可做（📖故事、⭐升星、⬆進階），右上「升」可**直接升一級**。
- 點牌開**彈出面板**（手機從下方滑出、桌面置中）：升級、升星、故事、進階、派駐、特性、台詞；「‹ ›」切換上一位／下一位（依目前排序與篩選），Esc 或點背景關閉。「⬆ 全部升級」（`levelUpAll`）一次升到買不起。程式在 `ui/disciplePanel.js`（`tile`、`disciplePopover`），彈出層掛在 `#dmodal`。
- **立繪**：把正方形圖放進 `assets/portraits/`，再到 `src/data/portraits.js` 登記「弟子 id → 路徑」即可，不用改程式；沒登記或載入失敗就顯示 emoji。詳見 `assets/portraits/README.md`。

## 碎片：弟子專屬 vs 通用
- **🧬 弟子專屬碎片**（`s.dshards[defId]`）：抽到、降服到**重複的弟子**時獲得（N 1／R 3／SR 10／SSR 30／UR 80，`RARITIES[].shard`），只能替**該弟子**升星；跨轉生保留。
- **🧩 通用碎片**（`s.res.shard`）：突發事件、委託、爆擊獎勵、道心兌換（6 道心 → 12）。用於專長心得；升星時專屬碎片不夠的部分也能用通用碎片抵（每 1 片專屬 = `CONFIG.disciple.shardSwap`＝2 片通用）。
- 升星花費表仍是 `CONFIG.disciple.starCost`（單位＝專屬碎片），支付邏輯見 `core/disciples.js` 的 `starPay`；弟子卡上顯示 `🧬 有/需` 加上不足時的 `＋🧩`。
- 平衡模擬器的機器人不會升星，所以這項改動沒有量到；改動前後的期望：每位 SSR 約 0.5%／UR 約 0.17% 每抽，重複才累積專屬碎片，三星 UR 需約 340 專屬碎片（約 4 個重複，其餘用通用碎片補）。

## 化神之後的內容
- **九重天劫**（`src/data/ascend.js`、`src/core/ascend.js`）：三重天、九道試煉，條件在化神時成立且多半看「本輪」表現（引爆、連鎖、事件、忍氣吞聲、秘境、限時化神），要靠轉生反覆挑戰。達成後按「渡劫」領道心、永久加成與後日談故事；進度跨轉生保留。新增一劫只要在 `TRIALS` 加一筆資料。
- **道果**：九劫全渡後，道心商店開放三項沒有實際上限的永久加成（`gate: 'ascend'`）。
- **弟子終章**：有第二章的 17 位弟子在升到 3 星後可讀第三章（`STORIES3`）。
- **轉生後事件**：突發事件與離線事件可用 `minReb` 限定「至少轉生幾次」才會出現；化神專屬事件用 `minRealm: 13`。

天劫平衡（12 種子、40 小時、`smart` 最佳化機器人且**不刻意追條件**）：開啟天劫與道果對轉生節奏幾乎沒有影響（40 小時 17.4 輪 vs 17.3 輪，在雜訊內，永久加成本來就小）。門檻依機器人每輪實際表現訂（引爆 6~13、連鎖 12~15、事件 10~19、忍 76~150、秘境 7~18、第一輪 3.2 小時、之後約 2.2 小時）：第一重天第一輪就過，後兩重要靠限時（2 小時）、連鎖 14（要拖久一點填滿復仇簿）、秘境 12 次等互相拉扯的條件，機器人約第 6~10 世才全部渡完；「轉生 8 次」是最硬的下限（約第 9 世）。調門檻請用 `RUNSTATS=1` 先量表現。

## 勢力宿敵
- 6 位勢力宿敵（`side`：焦烈、莫問鋒、宋清歡、寒千山、鐵無歸、孟百川），各代表一個勢力，**該勢力威望達第 2 階「聞風喪膽」且境界夠了才現身**，彼此獨立，不計入「舊債還清」。解鎖條件在 `cond: { faction, tier, minRealm }`。
- 場上（訪客＋復仇簿）同時最多 3 位宿敵（`CONFIG.nemesis.maxPresent`），避免多位同時解鎖時佔滿復仇簿。
- 每位宿敵可有專屬覺醒登場詞 `awakenTaunts`（3 階）；每位宿敵自動有一個擊敗稱號（由資料產生）。
- 模擬器：`hunt` 旗標讓機器人在化神多留一會兒等宿敵（`HUNT_MIN` 調上限，預設 20 遊戲分鐘），`NO_SIDE=1` 移除勢力宿敵當對照，`RUNSTATS=1` 會印出宿敵／覺醒進度與「抵達化神」時間。比較節奏請看「抵達化神」，不要看整輪耗時（hunt 會多停留）。
- 平衡（12 種子、40 小時、hunt）：有／無勢力宿敵的抵達化神時間在雜訊內（第 1 輪 3.14 vs 3.11 小時；40 小時轉生 16.8 vs 16.4 次）；累計道心 +14%（宿敵擊敗與覺醒的一次性道心）。勢力宿敵累計：第 1 輪 1.8/6、第 4 輪 4.8/6、第 8 輪 6/6；全宿敵覺醒約第 8~10 輪全滿（機器人狩獵時）。

### 收藏節奏（招賢令）
- 引爆的招賢令乘數 `CONFIG.gacha.burstTokenScale = 0.1`（原 1）；自然產出由每小時 30 張降為 15 張（`tokenTrickleSec` 120→240）。稀有度權重 SSR 4→3、UR 1→0.5（有保底）。
- 機器人（接近最佳操作）集滿 41 位：原本約 2 小時；調整後中位數約 11 小時（9~20 小時，6 組種子）；一般玩家預估約 20~30 小時。
- 量測：`TOKSCALE=0.1 JSON=1 node tests/sim.mjs 48 equip branch commission insight smart rebirth ascend`，看 SUMMARY 的 `tAll`（秒）。

### 離線調整
商店「神遊太虛」上限 8→12 級（離線最多 20 小時，第 12 級約需 690 道心）；離線效率上限 80%（「守廟靈獸」改為最多 6 級，剛好 50%→80%）。
